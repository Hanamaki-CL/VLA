# 项目介绍与个人贡献

## 对外介绍

**项目名称：MealVLA：面向配餐应用的视觉—语言—动作机器人操作框架**

**定位：个人机器人软件与具身智能应用项目。**

传统配餐机器人通常依赖预定义流程、固定目标位姿和较多任务配置。MealVLA 探索把语言条件操作策略接入已有机器人软件思路：利用 SmolVLA 根据图像、指令和状态预测动作，再通过执行约束与任务状态管理形成完整流程。

首版以公开 LIBERO 抓取放置任务为验证载体，围绕真实工程问题组织代码：数据是否一致、动作是否过期、模型和控制器是否使用同一动作空间、失败如何记录、实验是否可复现。

## 与已有经历的联系

| 已有经验 | 在新项目里的延伸 |
| --- | --- |
| Flexiv 末端控制与抓取搬运 | 对动作坐标系、控制模式和执行稳定性的理解 |
| ROS 2 Topic/Service 和控制接口 | 分离模型推理与执行层，设计消息契约 |
| YASMIN 任务状态机 | 执行状态、有限重试、失败分类和流程终止 |
| 配餐、称重和配重任务 | 用真实业务需求解释为什么研究语言条件操作 |
| Python 与视觉算法 | 数据处理、模型适配、实验和日志分析 |

这条叙事表达的是从机器人控制与应用开发向具身智能的延伸。不能把实习期间已有项目的成绩直接归到 MealVLA，也不能把新项目写成已经在企业生产线上部署。

## 个人贡献怎么讲

1. **系统设计：**定义观测、语言、动作块和执行结果的统一接口，划分模型、仿真、执行和评估职责。
2. **数据工程：**编写按任务分层的 episode 划分与重新导出流程，保存来源版本和映射，避免使用混合数据统计训练。
3. **模型接入：**对接 SmolVLA 及 checkpoint 预处理流程，处理图像方向、状态表示和动作反归一化。
4. **执行逻辑：**设计动作前缀执行、过期拒绝、非法动作拒绝及有限回合重试。
5. **实验工程：**实现逐回合日志、首次/最终成功率、延迟和置信区间统计，保留完整配置。

其中“设计/编写”已经有源码可查看；“运行有效”“提升性能”需要后续实验支撑。
