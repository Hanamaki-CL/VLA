# 运行指南

以下命令在仓库根目录执行。环境与实验的验证进度见 [STATUS.md](STATUS.md)。

## 环境

目标配置为 Linux、Python 3.11、RTX 5090。安装脚本固定使用 PyTorch 2.7.1 / torchvision 0.22.1 的 CUDA 12.8 wheel，以及 LeRobot 0.4.3。开始前确认 NVIDIA 驱动正常，`nvidia-smi` 能识别显卡。

还需要 FFmpeg 和 EGL/OpenGL 运行库。Ubuntu 上对应的软件包包括 `ffmpeg libegl1 libgl1 libglib2.0-0`，需根据机器环境安装。

```bash
bash scripts/setup_5090.sh
source .venv/bin/activate
export MUJOCO_GL=egl
mealvla doctor --cuda-check
python -m pip freeze > environment-resolved.txt
```

`doctor --cuda-check` 执行一个 CUDA 前向/反向运算，并打印设备与软件版本。模型加载和 EGL 渲染需要通过后续训练与评估命令分别验证。

## 数据准备

默认使用 `HuggingFaceVLA/libero` 中 `libero_object` 的三个任务。任务 ID 和原始指令可先通过以下命令查看：

```bash
mealvla tasks --suite libero_object
mealvla prepare --config configs/data.json
```

导出时按任务分层、按完整 episode 划分集合，保存到：

```text
data/libero_mealvla/
├── manifest.json
├── train/
│   ├── meta/stats.json
│   └── source_episodes.json
├── validation/
└── test/
```

三个子集分别生成统计量。训练入口只接受导出完成的 `train` 目录，评估使用 checkpoint 中保存的训练统计。

源数据缓存按 Hub revision 隔离。`manifest.json` 记录解析后的 revision、任务和 episode 划分；复现时可把该 revision 填入数据配置。导出使用图片格式，下载与磁盘占用取决于源数据规模；任务筛选不保证减少源数据下载量。

输出路径已存在时命令会退出。中断的导出目录可保留排查，重新运行时指定新路径。

## 训练

`configs/train_5090.json` 的起始参数为 batch size 8、20,000 steps、chunk size 50，冻结视觉编码器、训练动作专家。根据实际显存调整 batch size；先用少量 steps 检查完整训练链路，再进行正式实验。

```bash
mealvla train --config configs/train_5090.json --print-only
bash scripts/train_5090.sh configs/train_5090.json
```

`--print-only` 输出最终 argv，仍会检查训练数据是否完整。实际训练调用 LeRobot trainer，默认关闭 Hub 上传和 WandB。

训练目录旁的 `.launch.json` 记录配置与数据 manifest；checkpoint 包含模型及预处理/后处理配置。归档时同时保存环境列表、基础模型的 Hub snapshot revision 和训练日志。断点恢复需使用上游 trainer 的恢复参数，当前命令封装未提供 resume 选项。

## 评估

修改 `configs/eval_libero.json` 中的 checkpoint 路径，确保模型输入和动作空间与 LIBERO 一致：

```bash
bash scripts/evaluate_5090.sh configs/eval_libero.json
mealvla report outputs/eval/mealvla_seed42_h10
```

通用 `lerobot/smolvla_base` 可能使用不同的相机和机器人状态配置；当前评估入口要求经过 LIBERO 任务适配的 checkpoint。

每次消融实验使用新的输出目录，并固定任务、初始状态与种子。基础设施错误会使 manifest 标记为 `aborted`；部分结果的 `complete` 字段为 false。指标定义见 [EXPERIMENTS.md](EXPERIMENTS.md)。

## 测试与 mock 联调

```bash
python -m pip install -e '.[dev]'
python -m pytest
mealvla demo --output outputs/mock-demo
```

单元测试覆盖数据划分、动作队列、执行限制和报告统计。Mock 路径使用固定动作，只检查执行与日志流程。

## ROS 2

在可导入 `rclpy` 的环境中安装 MealVLA 核心包，然后运行：

```bash
python ros2/action_guard_node.py
```

节点订阅 `/mealvla/action_proposal`，向 `/mealvla/action_validation` 发布校验回执，不向机械臂发送动作。ROS 2 和模型训练可以使用独立 Python 环境，以避免系统 `rclpy` 与训练虚拟环境版本冲突。

## 故障排查

| 现象 | 检查项 |
| --- | --- |
| `no kernel image` | torch 的 CUDA 构建、GPU 架构支持与驱动版本 |
| CUDA OOM | batch size、其他 GPU 进程、实际可用显存 |
| 相机键不匹配 | checkpoint 的 input features、保存的 processor 与任务数据 |
| EGL 初始化失败 | Linux 图形库、GPU 驱动、容器设备透传 |
| 找不到任务数据 | suite、task ID、源数据 revision 与英文任务文本 |
| action 越界 | 反归一化统计、relative 控制模式与训练动作空间 |
| deadline 超时 | 推理耗时分布、TTL 和执行步数；当前推理为同步调用 |
