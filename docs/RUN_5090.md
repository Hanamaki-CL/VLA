# RTX 5090 操作指南

本文件是目标机器的运行手册。本次交付没有执行其中命令，也没有测得训练时长或显存峰值。

## 环境选择

推荐独立 Linux 环境，Python 3.11。安装 NVIDIA 驱动后，先确认 `nvidia-smi` 能识别目标显卡。标准 RTX 5090 为 32GB；如果是其他 5090 版本，按实际显存调整配置。

安装脚本明确使用 PyTorch 2.7.1 / torchvision 0.22.1 的 CUDA 12.8 wheel，以匹配 Blackwell，同时符合 LeRobot 0.4.3 的 torch `<2.8` 和 torchvision `<0.23` 约束。这是固定版本的候选环境，不自动升级到最新版本。

Linux 还需可用的 FFmpeg 和 EGL/OpenGL 运行库。Ubuntu 可由环境管理员安装 `ffmpeg libegl1 libgl1 libglib2.0-0`。本项目不自动执行系统包安装或驱动修改。

```bash
cd /path/to/mealvla
bash scripts/setup_5090.sh
source .venv/bin/activate
export MUJOCO_GL=egl
mealvla doctor --cuda-check
python -m pip freeze > environment-resolved.txt
```

`doctor --cuda-check` 仅验证一个 CUDA 前向/反向运算，不等于验证 SmolVLA 或 EGL。完整验证仍需要实际模型加载和仿真运行。

## 数据准备

查看官方任务列表，并保持数据和评估配置里的任务一致：

```bash
mealvla tasks --suite libero_object
mealvla prepare --config configs/data.json
```

首次运行下载公开数据并导出指定三个任务。下载量和磁盘占用取决于上游数据；导出为图片格式以简化视频编码依赖，磁盘成本可能较高。源数据可能整体下载，脚本并不保证按任务节省下载量。

输出：

```text
data/libero_mealvla/
  manifest.json
  train/meta/stats.json
  train/source_episodes.json
  validation/
  test/
```

manifest 为 `complete` 才允许训练。导出中断后使用新的输出目录重新运行，保留已有数据以便排查。首次解析的上游 revision 会写入 manifest；后续复现可将该值填入 `configs/data.json` 的 `revision`。

## 训练设置

默认配置：batch size 8、20,000 steps、chunk size 50、执行步数 10；冻结视觉编码器、训练动作专家。这是起始配置，不代表推荐参数已经在 5090 上测得最优。

建议先复制训练配置到新的文件，用较少 steps 完成实际加载和一个短训练阶段，再运行正式配置。不要据短训练损失下降就宣称任务学会了。

```bash
mealvla train --config configs/train_5090.json --print-only
bash scripts/train_5090.sh configs/train_5090.json
```

`--print-only` 仍要求数据导出完整，用于检查最终命令。训练调用官方 LeRobot trainer，默认关闭 Hub 上传与 WandB。需要恢复训练时，应使用上游的完整 checkpoint 恢复方式；本封装不冒充已实现断点续训接口。

训练输出旁的 `.launch.json` 保存配置和数据来源，trainer 保存权重及 processor。将基础模型实际下载的 Hub snapshot revision、完整环境列表和训练日志归档，以获得更强的复现能力。

## 仿真评估

确认实际生成的 checkpoint 中包含模型权重、config 和预处理/后处理配置，然后填写 `configs/eval_libero.json`。

```bash
bash scripts/evaluate_5090.sh configs/eval_libero.json
mealvla report outputs/eval/mealvla_seed42_h10
```

评估要求 LIBERO 动作空间匹配的微调 checkpoint。通用 `lerobot/smolvla_base` 的相机和机器人状态配置可能不同，不能直接冒充 LIBERO 零样本基线。基线模型应明确其数据、动作空间和归一化来源。

输出目录已存在会报错。每次消融使用不同的目录，并保留 task IDs、初始状态、随机种子和 checkpoint 一致。程序因依赖、显存或渲染错误中断时，manifest 标记 `aborted`，部分结果不能当作完整实验。

## 常见问题

| 现象 | 检查方向 |
| --- | --- |
| `no kernel image` | 确认 torch 为 cu128 构建、驱动支持，避免安装后被依赖替换成不支持该架构的版本 |
| CUDA OOM | 降低 batch size；检查其他 GPU 进程；记录修改，不假定显存一定足够 |
| 相机键不匹配 | 确认是本项目输入约定训练的 checkpoint，核对 saved processor 与 config |
| EGL 初始化失败 | 检查 Linux 图形库、GPU 驱动和容器设备透传，不属于策略效果问题 |
| 数据任务找不到 | 核对 suite、task ID、源数据 revision 和原始英文文本，脚本会显式报错 |
| action 越界 | 核对反归一化、训练动作空间和 relative 控制模式，不要直接放宽约束掩盖问题 |
| deadline 失败 | 记录推理时长，合理调整 TTL；同步推理不能提供实时中断保证 |

## ROS 2 可选示例

在已有 ROS 2 Python 环境中安装 MealVLA 核心包，并运行：

```bash
python ros2/action_guard_node.py
```

这是 dry-run 校验节点。ROS Humble 的常见 Python 版本与训练环境不同，可分开环境部署核心包；不要强行把系统 rclpy 混入 Python 3.11 训练虚拟环境。
